# Checklist 01 — Orientation (The First Screen)

These decide whether a visitor understands the project in the first ten seconds.
Everything here should land above the fold — before any scrolling.
Rate each: PRESENT / PARTIAL / MISSING

- [ ] **1.1 One-Line What-It-Is**
  A single sentence in the first screen stating what the project IS, in plain language.
  Not a tagline pun — a concrete description a stranger can repeat back.

- [ ] **1.2 Problem It Solves**
  States the problem or pain the project addresses. A reader should learn why this
  exists, not just what it does.

- [ ] **1.3 Who It's For**
  Names the intended audience (developers, ops, end users) or use case. Lets a reader
  self-select in or out within seconds.

- [ ] **1.4 Working Example Above the Fold**
  A runnable snippet, command, or screenshot near the top showing the project in action.
  For libraries/CLIs: a code/command block. For apps/services: a screenshot or demo.

- [ ] **1.5 Project Status / Maturity**
  Signals whether this is experimental, beta, stable, or maintained — via badge, a status
  line, or an explicit note. Prevents wasted time on abandoned or pre-alpha work.

- [ ] **1.6 "Is This For Me" Clarity**
  A reader can decide in the first screen whether to keep reading. The combination of
  what-it-is, problem, and audience answers "does this solve my problem?" without scrolling.

- [ ] **1.7 Name and Purpose Aligned**
  The project name plus the first sentence are not contradictory or cryptic. If the name is
  abstract, the first line grounds it immediately.
