# Checklist 04 — Maintenance, Trust & Hygiene

These signal that the project is maintained, contributable, and trustworthy — and that the
README itself is not rotting. Broken links and stale badges erode trust fast.
Rate each: PRESENT / PARTIAL / MISSING

- [ ] **4.1 License Present**
  A license is stated in the README and a LICENSE file exists. Without it, the project is
  legally unusable by others regardless of intent.

- [ ] **4.2 Contributing / Dev Setup**
  How to contribute or set up a development environment — CONTRIBUTING file or a README
  section. Covers running tests and the local dev loop, not just usage.

- [ ] **4.3 Troubleshooting / FAQ**
  Common errors and their fixes, or answers to predictable questions. Saves users from
  filing issues for known footguns.

- [ ] **4.4 Links to Deeper Docs**
  Pointers to fuller documentation (docs site, wiki, `docs/`) where the README intentionally
  stays brief. The README is an index, not a dead end.

- [ ] **4.5 Badges Accurate (Not Stale)**
  Any badges (build, version, coverage) reflect reality and point at live endpoints. No
  badge frozen on an old CI provider or a dead version.

- [ ] **4.6 Versioning / Changelog Pointer**
  A link to releases, a CHANGELOG, or a stated versioning policy. A user can tell what
  changed between versions and whether an upgrade is safe.

- [ ] **4.7 No Broken or Placeholder Links**
  No `TODO`, `TBD`, `lorem ipsum`, `coming soon`, `example.com` placeholders, or links to
  moved/missing pages, anchors, or images. Every link resolves.

- [ ] **4.8 Support / Contact Channel**
  Where to get help or report bugs — issue tracker, discussion forum, or contact. A user
  who is stuck knows where to go next.
